# Technical Stack

AI-powered AAC assistant — a child-facing communication board (phone, tablet, laptop),
a teacher/SLT analytics dashboard, and an MCP analytics server. One repo, **one Next.js
process**, one deploy. This document describes what is actually running; per-feature
detail lives in [`docs/feature/`](./feature/README.md).

## Stack as built

| Concern | Choice |
|---|---|
| Framework | Next.js 15 (App Router) + React + TypeScript strict |
| Styling | Tailwind v4; inline-SVG symbol set coloured by the Fitzgerald key |
| State | Plain React state — no state library |
| Local storage | Raw IndexedDB (event queue), `localStorage` (voice choice) — no Dexie |
| Offline | Hand-written service worker (`public/sw.js`) + web app manifest |
| Speech | Web Speech API `speechSynthesis` only — cloud TTS deliberately absent |
| Database | **`node:sqlite`** (built into Node ≥ 24), WAL mode. No ORM, no better-sqlite3, no Drizzle — plain SQL throughout |
| Validation | Hand-rolled per-boundary validation (closed event-name lists, JSON Schema for MCP tool args) — no Zod |
| Auth | Adults: scrypt-hashed credentials + signed httpOnly session cookie (`lib/auth.ts`). Children: picture sign-in at `/who` (`lib/session.ts`) — a data-integrity fix, not security |
| Routing | Three public hostnames → one origin; `middleware.ts` reads `Host` and 404s cross-surface routes |
| MCP server | Zero-dependency JSON-RPC 2.0, stdio (`mcp/server.ts`) **and** HTTP (`POST /api/mcp`, bearer token). **20 tools** over `aac.db` |
| Analytics pipeline | Python: `tools/build.sh` rebuilds `aac.db` deterministically — seed, rollup, 8 SQL insight rules, safety verification gate |
| Deploy | macOS launchd + Cloudflare Tunnel (`deploy/`, runbook in [`deploy.md`](./deploy.md)) — not Railway/Fly/Vercel |

Two databases: `aac.db` (analytics — events, utterances, metrics, insights) and
`aac_app.db` (app state — adult accounts, card overrides, categories, generated
pictures). Both SQLite WAL; a WAL writer and its readers must share a filesystem,
which is why everything is one process on one machine.

## AI integration as built

### Images — a provider chain, not a single vendor

`lib/visuals/provider.ts` selects whichever image service is actually configured,
in order:

1. **Vertex AI** — `gemini-2.5-flash-image` via GCP ADC (**the verified-working path**)
2. **Gemini AI Studio** — API key
3. **OpenAI** — API key fallback

Runtime pictures resolve through the ladder in `lib/visuals/ladder.ts`
(five rungs, cheapest first: built-in symbol set, then cached and shared pictures,
then a provider call — only the last rung costs money),
with sanitisation in `lib/visuals/sanitize.ts` so only a bare concept — never a child's
name — leaves the machine. Build-time vocabulary icons are pre-generated by
`tools/generate-icons.mjs` into `public/icons/ai/` (see
[`feature/kid-app/ai-vocabulary-icons.md`](./feature/kid-app/ai-vocabulary-icons.md)).

### Chat — the Ask panel

`lib/chat/` implements one `ChatProvider` interface with OpenAI and Gemini
implementations; the agent loop (`lib/chat/agent.ts`) calls the MCP tools in-process,
bounded steps, with a forbidden-action guard that scans answers for advice AAC practice
rules out (resizing grids, moving learned buttons).

There is **no local Gemma / Ollama analysis device** in the current build; that remains
a design direction (below), not a shipped component. The deterministic layer never uses
a model: the 8 diagnostic rules are plain SQL views, materialised nightly by
`tools/run_rules.py`.

## Pinned decisions (still true)

- **No key in the browser.** All provider keys live in `.env.local`, server-side only;
  nothing lands in a `NEXT_PUBLIC_` var.
- **Rules are SQL, not LLM.** The diagnostic rules must be deterministic and explainable
  to a speech therapist. Every insight carries the `fired_rule_id` that justified it.
- **Communication never blocks on AI or logging.** Board, sentence bar, TTS and saved
  cards work with no network; a failed audit write never surfaces to the child.
- **Only sanitized concepts leave the machine.** Utterance text is consent-gated;
  image prompts carry a concept, never an identity.
- **Role and consent scoping live in the query/tool layer** (`lib/access.ts`, MCP
  handlers), never in a prompt.
- **Clinical constraints are code, not copy.** No card moves or resizes; neutral metrics
  are never styled good/bad; every number carries its `n`; a metric with no real source
  renders "not recorded", never `0`.

## Divergences from the original plan

The first version of this document was the pre-build plan. Where it differed from what
shipped:

| Planned | Shipped |
|---|---|
| Zustand, Dexie, Serwist, shadcn/ui, Recharts, TanStack Table | None — plain React, raw IndexedDB, hand-written SW and components |
| better-sqlite3 / Turso + Drizzle + Zod | `node:sqlite`, plain SQL, hand-rolled validation |
| `@modelcontextprotocol/sdk`, 5 tools | Zero-dependency MCP server, 20 tools |
| Local Gemma 3 4B on a separate analysis device | Not built; nightly analysis is pure SQL, narration via cloud chat providers |
| OpenAI `gpt-image-2` as the only image path | Vertex → Gemini → OpenAI provider chain |
| Railway / Fly / VPS | macOS launchd + Cloudflare Tunnel, no inbound ports |
| 7 insight rules | 8 rules (I1–I8) |
| transformers.js MiniLM in-browser embeddings | Not built; semantic matching uses provider embeddings server-side |
